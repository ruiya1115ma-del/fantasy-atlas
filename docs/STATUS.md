## A. 无法在本机完成（环境限制，不是代码问题）

### A1. 生产构建 `next build` 未通过

- **现象**：`next build`（Turbopack）在静态生成阶段报
  `Error [DataCloneError]: () => null could not be cloned`；
  `next build --webpack` 报 `Error: spawn EPERM`。
- **原因**：本机沙箱禁止 fork 子进程，而 Next 的构建 worker 需要 fork；
  Turbopack + `workerThreads` 组合在 Next 16.0.7 上另有 DataClone 问题。
- **已做的替代验证**：`tsc --noEmit` 0 错误、dev 模式全部路由 200、
  25 个单元断言 + 9 个 HTTP 冒烟断言全绿（见 `docs/TEST_REPORT.md`）。
- **你需要做的**：在允许 fork 的机器 / CI / Vercel 上跑一次 `npm run build` 确认。

### A2. 浏览器端自动化 E2E 未建立

- 目前只有 HTTP 层冒烟（状态码 + 关键文案），没有 Playwright/Cypress。
- 影响：点击、轮播切换、抽屉开合这类交互是手工点过 + 截图确认的，**没有回归保护**。

### A3. 无障碍（a11y）与 Safari 未验证

- 只做了基本的 `focus-visible`、`aria-label`、语义标签、`prefers-reduced-motion` 降级。
- 未跑 axe 扫描，未做完整键盘遍历测试，未在 Safari/Firefox 实机验证。

## B. 数据与图片（当前最需要你注意的一节）

### B1. 豆瓣抓取还没跑完 → 部分作品暂时没有真实海报

- 站点已接豆瓣：评分、导演、主演、类型、片长、剧情简介、海报、剧照全部走豆瓣条目
  （`scripts/fetch-douban.mjs`，串行 + 节流，避免被封）。
- **当前实测**：274 部作品中，**274 部有真实海报**（豆瓣 108 / IMDb 144 / 维基 22）、108 部有剧照、
  159 部有评分（豆瓣 108 + IMDb 兜底）；缺海报 29 部（其中 20 部是芭比动画/剧集等豆瓣限流或维基无条目的片子）。
- **失败原因不是"查不到"，多半是豆瓣单条目 IP 限流**：返回 `HTTP 400` +
  `subject_ip_rate_limit` / `code 1309`。脚本已对 1309 做 45s→120s 退避重试，但一次跑太多仍会被拦。
- 补齐方式（可反复续跑，已抓到的不会重复抓）：

```bash
node scripts/fetch-douban.mjs            # 只补缺；被限流时等一会儿再跑
node scripts/fix-douban-records.mjs      # 剔除错配（评分 0 / 年份差 3 年 / 标题对不上）
node scripts/fetch-posters.mjs           # 维基兜底
node scripts/merge-catalog.mjs           # 合并进 catalog.json
node scripts/report-coverage.mjs         # 看覆盖率与还差哪些
```

- 覆盖率实时数字见 `data/reports/coverage.txt`（由最后一条命令生成）。
- 两边都没有的作品，页面明确显示"暂无可用海报"，**绝不用 AI 图或别的电影图顶替**。

### B2. 少数片名的自动匹配会失败，需要人工指定豆瓣条目

- 例如芭比系列的部分片、纳尼亚、木乃伊 3 等，豆瓣标题与片单中文名写法不同，
  自动匹配会保守地放弃（宁可不配图，也不错配）。
- 处理方式：在 `data/raw/douban-hints.json` 里写 `{ "片单id": "豆瓣条目数字ID" }`，
  再重跑 `node scripts/fetch-douban.mjs`。失败清单与候选见 `data/reports/coverage.txt`。

### B3. 海报是引用，不是授权

- 海报/剧照版权归发行方；本站只在个人非商业范围引用并逐条标注来源条目。
- 若要公开发布或商用，必须换成已授权素材（或删掉图片数据全站回退程序化封面）。

## C. 内容与功能上的裁剪

### C1. 推荐页保留但不在主导航

- 按"只保留四个主要页面"的要求，导航只有：首页 / 探索 / 我的收藏；
  详情页从卡片进入。推荐页（`/recommend`）与数据来源页（`/sources`）作为工具页保留，
  分别从首页入口与页脚进入。

### C2. 只抓了「看过的片单」，没有做播放源 / 社区 / 评分榜

- 站点不做排行榜、不做社区、不做播放链接，这是刻意的裁剪（你说过不要）。

### C3. 剧照数量

- 每部默认抓 2 张剧照（`--stills=N` 可调）。豆瓣每部有几百到几千张，抓更多会显著变慢，
  也会给对方服务器增加压力，所以默认克制。
